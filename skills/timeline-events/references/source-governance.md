# 研究核验与出版治理规范

## 事实状态

1. **图片转录**：`reference_transcription`，仅抄录可见信息；无需额外证据，但必须说明尚未独立核实。支持用户要求“不增删原图内容”。
2. **候选条目**：研究 Agent 收集事件，保存 URL、截取必要说明和待核验问题；暂不公开为 `verified`。
3. **证据核对**：逐条阅读原文，对日期、主体、发生状态、数字的单位与口径交叉核查；重大争议需第二来源与解释。
4. **编辑确认**：保留争议和不确定性，移除来源无法支持的结论；自动验证不能替代编辑确认。
5. **已验证上线**：`verified`，并确保同名来源清单可访问，且资料截止时间准确。

## 来源颗粒度

最低每个 `event` 一条来源映射 `source_ids`；同一证据可支持多个节点但需实际证明对应主张。来源对象包括出版者、原始标题、永久 URL；后续扩展可加访问时间、发布日期、摘录位置、核验说明，但要同步 schema。

**危险混淆**：政府/媒体官网首页不是该事件的证据网址。不能为了通过 URL 格式校验而填一个真实首页并声称核验完成。

## 词汇规范

| 现实状态 | 推荐措辞 | 避免错误 |
|---|---|---|
| 政策公布 | 宣布、提出、拟议 | “已生效” |
| 法规签署 | 签署、批准 | “全面执行” |
| 临时安排 | 暂缓、暂停、延期至明确日期 | “战争结束”“零关税” |
| 谈判取得进展 | 讨论、达成原则、联合声明 | “最终协议” |
| 法院判决 | 裁定某法律依据/具体争点 | 推断所有其它法律框架失效 |
| 预测性内容 | 预计、计划、尚待完成 | 写成确定事实 |

## 发布门禁

对照每个节点生成审计记录：`event_id / date / claim / sources / supports? / uncertainty / editor / verified_at`。源数据改写后需要重新审计；不得继续沿用之前版本的 `verified` 状态。动态事件不能自动套用历史结论或把运行日写成最新核实日。

## 未核验复刻示例

`examples/reference-image-transcription.json` 从用户图片抄录，可能含有仍需核对的关税税率、司法判决及 2026 年外交进展。因用户要求版式**一模一样**，保留其原始说法，但页面附有免责声明，首页标注“原图复刻 · 尚未核验”。如需正式事实版，应按研究模式重新取得原始出处，建立另一个核验版本；绝不在复刻 JSON 中悄悄修改数值。
